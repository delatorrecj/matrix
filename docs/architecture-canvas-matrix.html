3. What happens when the user submits a scenario

End-to-end path from cockpit / ScenarioBuilder through WebSocket completion.

3.1 Input composition

Structured builder → NL sentence

ScenarioBuilder.buildScenarioQuery turns form state into a controlled English sentence:

  • lane_closure → “Close N lane(s) on <LOC>.”
  • full_closure → “Fully close <LOC>.”
  • speed_change → “Reduce speed to K km/h on <LOC>.”
  • capacity_change → “Change capacity to P% on <LOC>.”
  • new_facility → “Build a 3,000-seat school at Molo.”

Cockpit free-text / presets

Presets like “What if we build a 3,000-seat school in Molo?” post the same POST /scenario body.

Right-click “use location” inserts coordinates into the NL string, not structured GeoJSON (live UI reality).

3.2 REST parse + persist

  1. POST /scenario with { query, input_type: "nl", geometry? }
  2. annotate_query_with_gazetteer(query) rewrites Hiligaynon / colloquial place names
  3. GraphRAG retrieve(query, top_k=3) grounds the orchestrator
  4. Azure OpenAI returns structured ScenarioSchema: intervention_type, location, parameters, description
  5. db.save_scenario stores raw_input, parsed_params, optional PostGIS geometry
  6. Client navigates to /scenario/{id} and opens the WebSocket

4. How the actual simulation works

Two intervention families share one kernel: network edits vs demand edits.

Road interventions

lane_closure · full_closure · speed_change · capacity_change

  1. Resolve affected SUMO edges (geometry → gazetteer → keyword → busy-edge fallback)
  2. apply_intervention issues TraCI edits (disallow lanes / setMaxSpeed / speed×factor proxy)
  3. Existing demand re-routes around capacity loss
  4. Modules score Δtrips vs Redis baseline edge_counts

New facility (demand-only)

new_facility — school / market / terminal

  1. resolve_intervention_site returns ([], "facility-demand") — no corridor TraCI
  2. prepare_facility_demand builds BEH-4 gravity trip list
  3. inject_facility_demand adds ≤80 sample vehicles via findRoute
  4. BEH-4 exposes full demand total; other dims react to injected edge activity

Kernel simulate loop

  1. Start SUMO TraCI on Iloilo .net.xml + route file
  2. Apply intervention (or no-op for facilities)
  3. Optionally inject facility vehicles
  4. Step to SIM_END (default 900 s AM-peak window)
  5. Emit FCD frames + edgeData → Trajectory{edge_counts, frames, meta}
  6. Score five modules on that same trajectory vs baseline
  7. Citation-guarded Azure synthesis → BLUF brief

6. How the maps work & how location is determined

Mapbox base + Deck.gl overlays; location resolution is an ordered fallback chain.

Map surfaces

  • Base: Mapbox GL, default view lon 122.56, lat 10.72, zoom 13, pitch 45°
  • Clamp: Iloilo pilot bbox lng 122.48–122.62 · lat 10.64–10.79 · minZoom 11
  • TripsLayer: animated agents from PLAYBACK_FRAME
  • Congestion: GeoJSON edges keyed by edge_id ← EDGE_COUNTS
  • Flood / confidence: static public/layers/*.geojson
  • Pin / camera: honest corridor midpoint, else location_of_interest

Location resolution priority

  1. Structured GeoJSON on POST /scenario (Point/Polygon). Centroid → edges via geometry.resolve_geometry or facility lon/lat.
  2. Hiligaynon gazetteer (gazetteer_iloilo.json): “Molo” → coords / sumo_edge / street alias.
  3. Street-name keyword scan against SUMO network edge names.
  4. Busy-edge fallback — deterministic hash into top-50 baseline edges; labeled honestly; no LoI pin.
Kernel OSM bbox: ILOILO_BBOX = (10.65, 122.50, 10.78, 122.61) — lat_min, lon_min, lat_max, lon_max. Facilities do not draw a corridor halo; the camera flies to gazetteer / map-drop LoI when available.

8. Data pipeline & warm caches

Open-data ingest offline; hot path depends on Redis + startup warmers.

Offline / nightly

  • data/fetch/* → raw OSM, CCHAIN, PSA, …
  • Build SUMO net + demand (build_demand.py)
  • Nightly baseline → Redis baseline:iloilo:latest
  • GraphRAG corpus ingest → Chroma

API startup

  • Warm persona pool: generate → audit → reweight
  • Redis personas:iloilo:v1 (+ audit key)
  • Ingest GraphRAG if empty
  • Health: GET /health

Per scenario

  • Parse + gazetteer + RAG
  • SUMO delta vs baseline
  • Cache traj scenario:{id}:latest
  • Persist runs / results / audit
